# Board Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A built-in Kanban board with boards, columns, cards and an activity log, switched on from Settings ("Board", off by default). Cards can link to a session, a Pilot or a Flow run, and they move forward on their own as that linked work starts and finishes.

**Architecture:** Board data lives in four normalized SQLite tables, with all reordering done in Rust transactions so positions stay contiguous and every move writes an activity row atomically. The frontend is a `board` app view built from a small set of React Kanban components on top of dnd-kit (pointer and keyboard sensors). The visual design follows the Gr8r Studio board (see Visual Design). Auto-movement is a single pure rule (`autoMoveTarget`) applied when a linked session or Flow run changes state.

**Tech Stack:** Rust + rusqlite, React 19 + TS, Tailwind v4 with the tokens in `src/styles/index.css`, `@dnd-kit/core` 6.3.1, `@dnd-kit/sortable` 10.0.0, `@dnd-kit/utilities` 3.2.2, Vitest.

**Spec:** Conversation decisions from 2026-10-23 ("inbuilt Kanban-style board … boards, cards, activity"; external board integrations later) and 2026-10-24 (an "Enable board" setting; use a drag-and-drop library instead of building from scratch; match the Gr8r Studio board design, https://gr8r-taskmanagement.vercel.app/ → a project → Board). Remaining choices are under Design Decisions.

## Global Constraints

- Tables are created by `crate::board::ensure_tables(conn)?;` at the end of `session_store::migrate`. No numbered migration. `PRAGMA foreign_keys` is already ON.
- Commands take `State<'_, SessionStore>`, return `Result<_, String>`, and emit `"rebase:board-changed"` with payload `{ boardId }` after writes.
- **Drag and drop uses dnd-kit only** (`bun add @dnd-kit/core@^6.3.1 @dnd-kit/sortable@^10.0.0 @dnd-kit/utilities@^3.2.2`). Never use the HTML `draggable` attribute or native `dragstart`/`drop` events on the board. Tauri's file-drop handling (`onDragDropEvent`, used by `useFileDrop.ts`, `FileTree.tsx`, `NotesView.tsx`, `useQuickAttachments.ts`) can swallow native drag events inside the window, and dnd-kit's pointer events are unaffected.
- **Visual design is ours.** Match the Gr8r board's look using our own React code and our tokens. Do not copy Gr8r source or CSS files.
- **Feature flag:** `rebase.boardEnabled`, default `false`. When off, the Board sidebar entry and view are hidden; data is kept.
- UI tooling uses Bun (root `CLAUDE.md`): `bun add`, `bun run <script>`, `bunx <tool>`; tests run through Vitest.
- Column roles are `"todo" | "doing" | "review" | "done" | null`. Each role appears at most once per board.
- External board integrations (Linear, Jira, …) are **out of scope**. The `link_kind` column is the extension point for them.
- Commits carry no Claude or co-author attribution. No local Cubic review for this repo (user directive).

## Design Decisions (my calls, flag if wrong)

- **Default columns** on a new board: Backlog (`todo`), In Progress (`doing`), Review (`review`), Done (`done`).
- **Positions are integers 0..n-1 per column**, renumbered inside the move transaction. No fractional indexing, because boards are small and local.
- **Card numbers.** Each card gets a per-board number shown as `#12` in a fixed-width font. Numbers come from a `boards.card_seq` counter, so a deleted card's number is never reused. This gives people and agents a short handle ("card #12").
- **Auto-move only goes forward.** When linked work starts, the card moves to `doing`. When it completes, the card moves to `review` if the board has that role, otherwise to `done`. When it fails, the card stays put and the activity log records `failed`. A card never moves to a column left of where it currently is, so a card the user already dragged to Done stays there.
- **Auto-move keeps running while the Board setting is off**, so cards are current when it's turned back on. With no boards, it's a single empty query.
- **Column deletion** is refused while the column holds cards (`"Column has N cards"`).
- **One link per card** (`link_kind`, `link_id`), kinds `"session" | "pilot" | "flow-run"`. Pilot links follow the Pilot's spawned sessions: a Pilot-spawned session that settles counts as activity for any card linked to that Pilot.
- **Actor** on activity rows is `"user"` or `"system"`.
- **The drop indicator is the dragged card's own slot.** While dragging, the card's sortable placeholder collapses to a 2px accent line, so neighbours slide apart to show exactly where it will land (Gr8r's drop line, with dnd-kit's animation).
- **The drag preview** (`DragOverlay`) is the only place the board uses a shadow and tilt (1.5°), as in Gr8r. Everywhere else it stays flat.

**Non-goals for v1:** labels, priorities, assignees, due dates, subtasks, collapsing columns, filter/search, and list/table/calendar views of a board. They're all in Gr8r; none are needed to track agent work.

## Review Focus

1. A card dropped onto a column of a *different board* (or a stale column id) must be rejected, not orphaned. `board_card_move` errors with `"Column not on this board"` (Task 1 test).
2. Two auto-move events for the same card at once, such as a Flow run finishing while the user drags it, must not duplicate positions. Moves serialize on the connection mutex, and a test asserts positions stay 0..n-1 after interleaved moves (Task 1 test).
3. When a linked session or flow run is deleted, the card keeps its link id, shows "Linked work no longer exists" and doesn't throw (Task 6 test).
4. Dropping a card in its own position is a no-op that writes **no** activity row and makes **no** command call (Task 1 and Task 4 tests).
5. A board with no `doing` column (the user deleted it) means auto-move on start is skipped, not an error (Task 2 test).
6. Esc during a drag, or a rejected `board_card_move`, puts the card back exactly where it was (Task 4 and Task 5 tests).
7. Board drag must not break file drop elsewhere: dropping a file on the composer still attaches it after using the board (Task 5 manual check).
8. Turning the setting off while the Board view is open closes the view, and turning it on again shows the same boards (Task 3 test, Task 5 manual check).

- Tables:

```sql
boards(id TEXT PRIMARY KEY, name TEXT NOT NULL, card_seq INTEGER NOT NULL DEFAULT 0, created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL)
board_columns(id TEXT PRIMARY KEY, board_id TEXT NOT NULL REFERENCES boards(id) ON DELETE CASCADE, name TEXT NOT NULL, position INTEGER NOT NULL, role TEXT)
board_cards(id TEXT PRIMARY KEY, board_id TEXT NOT NULL REFERENCES boards(id) ON DELETE CASCADE, column_id TEXT NOT NULL REFERENCES board_columns(id), number INTEGER NOT NULL, title TEXT NOT NULL, body TEXT NOT NULL DEFAULT '', position INTEGER NOT NULL, link_kind TEXT, link_id TEXT, created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL, UNIQUE(board_id, number))
board_activity(id TEXT PRIMARY KEY, board_id TEXT NOT NULL REFERENCES boards(id) ON DELETE CASCADE, card_id TEXT REFERENCES board_cards(id) ON DELETE CASCADE, kind TEXT NOT NULL, actor TEXT NOT NULL, from_column TEXT, to_column TEXT, detail TEXT, created_at INTEGER NOT NULL)
-- indexes: board_cards(column_id, position), board_cards(link_kind, link_id), board_activity(board_id, created_at DESC), board_activity(card_id, created_at DESC)
```

- Activity `kind`: `"created" | "moved" | "edited" | "linked" | "unlinked" | "started" | "completed" | "failed" | "deleted"`. A `deleted` row keeps `card_id = NULL` and stores `#<number> <title>` in `detail`.

  - `board_rename(boardId, name)`, `board_delete(boardId)`
  - `board_column_create(boardId, name, role?) -> Column`, `board_column_update(columnId, name, role?)`
  - `board_column_move(columnId, index)`, `board_column_delete(columnId)`
  - `board_card_create(columnId, title, body?) -> Card` (increments `boards.card_seq` and uses it as `number` in the same transaction)
  - `board_card_update(cardId, title, body)`
  - `board_card_move(cardId, columnId, index, actor)`
  - `board_card_link(cardId, linkKind?, linkId?)` (passing nulls unlinks)
  - `board_card_delete(cardId)`
  - `board_cards_for_link(linkKind, linkId) -> Vec<Card>`
  - `board_activity(boardId, cardId?, limit) -> Vec<Activity>`, newest first
